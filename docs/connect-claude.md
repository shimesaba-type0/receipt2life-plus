# Claude.ai から receipt2life に繋ぐ(MCP コネクタ)

AI(Claude)から、支出を登録・一覧するための接続手順です。実値(ドメインなど)は、ここには書きません。

## 前提

[setup.md](setup.md) の手順が済んでいること。

- Worker がデプロイされ、カスタムドメインが付いている
- Access で守られていて、ブラウザで `/healthz` を開くと、ログイン後に `{"ok":true}` が出る
- Access アプリの「追加設定」で **Managed OAuth** がオン
- 同じ画面の **許可するリダイレクト URI** に、Claude のコールバックURLが入っている
  - `https://claude.ai/api/mcp/auth_callback`
  - `https://claude.com/api/mcp/auth_callback`
  - 接続に失敗したときのエラーに、実際のURLが出る。違っていたら、そのURLを足す
- ローカルホスト系の許可(localhost / loopback)は**オフ**

## Claude.ai に追加する

カスタムコネクタの追加は、有料プランの機能です。追加は Web(claude.ai)かデスクトップで行います。一度設定すれば、スマホの Claude アプリからも使えます。

1. claude.ai → プロフィール → 設定 → コネクタ → **カスタムコネクタを追加**
2. 次のとおり入力する。

   | 項目 | 値 |
   | --- | --- |
   | 名前 | `receipt2life` |
   | URL | `https://<サブドメイン>.<ドメイン>/mcp` |
   | 認証 | 今すぐサインイン(検出済み) |
   | OAuth クライアント | 自動的に登録(検出済み) |
   | リクエストヘッダー | 追加しない |

3. 追加して「接続」を押す。Cloudflare Access のログイン画面が開くので、ログインして許可する。
4. チャットの入力欄の「＋」(ツール)メニューで、`receipt2life` をオンにする。

## 動作確認

チャットで、次のように頼みます。

1. 「500円のコーヒーを、現金で、今日付けで登録して」 → 「1件登録しました: …」と返る
2. 「今月の取引を一覧して」

## 使えるツール(30個)

| ツール | 役割 |
| --- | --- |
| `add_transactions` / `list_transactions` / `update_transaction` / `delete_transaction` | 取引の登録・一覧・修正・削除。明細(レシートの行)や、レシートの情報(時刻・電話・住所・登録番号など)つきで登録・修正できる。一覧は `keyword` で探せる。削除は `delete_photos` で写真もいっしょに |
| `summarize` / `list_categories` | 集計(明細があれば行ごとのカテゴリ・フラグで数える)、カテゴリと口座の一覧(カテゴリは大分類ごとのまとまりと、使っている支出の件数 `usage` つき) |
| `summarize_tax` | レシートに印字された消費税額を、期間ごとに税率別(`group_by: "rate"`。既定)または月別×税率別(`"month"`)に合計する。税の内訳が無い支出の件数・金額(カバレッジ)も返す |
| `add_category` / `update_category` / `delete_category` / `rename_group` | カテゴリの管理。Zaim のように大分類の下にサブカテゴリを作る(アイコンつき)・名前や大分類やアイコンを変える・削除(使用中は `move_to` で支出を移す)・大分類の名前を変える |
| `add_account` / `update_account` / `delete_account` | 口座(支払方法。現金・カードなど)の管理。追加・名前の変更・削除(使用中は `move_to` で支出を移す)。AI は利用者に確認してから使い、先に `list_categories` の `accounts` で既存を確かめて、表記ゆれで増やさない |
| `add_event` / `update_event` / `list_events` | 日付や期間のメモ(出来事) |
| `create_photo_upload_link` | 写真のアップロード用リンクを作る |
| `list_photos` | 写真のメタ情報(id、日付、紐づけ先、説明、種類、サイズ)の一覧 |
| `get_photos` | 写真の画像そのものを取得する(1回に1〜4枚、合計約6MBまで) |
| `add_seat_record` / `list_seat_records` / `update_seat_record` / `delete_seat_record` | 映画館などの座席の記録(作品名・公演名・会場・スクリーン/エリア・座席・席種・評価1〜5・一言)の登録・一覧(会場ごと・席ごとの平均評価つき)・修正・削除。会場・スクリーンは名前で指定し、無ければ自動で作る(応答の `created_venue` / `created_screen`)。登録前に `list_venues` で既存の会場・スクリーンを確かめ、同じ名前を使う |
| `list_venues` / `update_venue` / `update_screen` | 会場とスクリーンは座席の記録とは別のレコード。一覧(会場ごとのスクリーン、記録件数、平均評価、スクリーンの特徴 `note`)、会場名の変更、スクリーン名の変更と特徴 `note`(例「前方は首が疲れる」)の設定・消去。削除のツールはない |
| `add_link` / `list_links` / `delete_link` | Xの投稿・YouTubeの動画のリンクを、日付・取引・出来事に付けて残す・一覧・削除(URLだけ保存。タイトル取得や埋め込みはしない) |

## 座席の記録(映画の席を記録して、次の席選びに使う)

映画館のスクリーン・座席や、野球場の席種などの評価を、メモではなく構造化して残し、次に席を選ぶときに引けます。映画以外(劇場、ライブ会場など)にも使えます。作品名・公演名は `title` に入れます(明細の品名とは別。明細は取引の品目、`title` は座席の記録に持つ催しの名前)。

| 項目 | 内容 |
| --- | --- |
| `date` / `venue` / `seat` | 必須。日付、会場名、座席(例: `F-5`) |
| `title` | 作品名・公演名(映画のタイトル、ライブ名など。100文字まで。任意。会場・スクリーン・座席とは別の、そのときの催しの名前) |
| `seat_class` | 席種(プレミアムシート、内野指定席、ボックスシート、外野自由席など。50文字まで。任意)。座席番号 `seat` とは別に、その席の種類を入れる。次の席選びで「この席種は良かったか」を引けるので、できるだけ入れる。`list_seat_records` で部分一致で絞り込める |
| `screen` | スクリーン・ホール・エリア名(任意)。映画館のスクリーンだけでなく、ホール・ブロック・エリアなどの区画にも使える。会場の下のレコードで、`update_screen` で特徴 `note` を付けられる |
| `rating` | 席の評価。整数の1〜5、5が最良(任意。範囲外はエラー) |
| `note` | 一言(200文字まで。例「前すぎて首が疲れた」) |
| `transaction_id` | チケット代などの取引への紐づけ(任意。取引を消しても記録は残り、紐づけだけ外れる) |

- 登録: 「今日の映画、A映画館のスクリーン5のF-5は前すぎて首が疲れた。★2で」と頼む。AI はまず `list_venues` で既存の会場・スクリーンを確かめて、同じ名前を使って `add_seat_record` で登録する。新しい名前を作る前には、あなたに確認する(表記ゆれで同じ会場の記録が分かれないようにするため)。登録の応答の `created_venue` / `created_screen` が true なら新規に作ったので、既存の表記と違っていないかも確かめる。評価を言わなかったら `rating` は省略する
- 席選び: 「A映画館のスクリーン5のF-5ってどうだった?」と聞くと、AI が `list_seat_records`(`title`(部分一致)/ `seat_class`(部分一致)/ `venue` / `screen` / `seat` で絞る)で過去の評価(`rating`・`note`)と平均評価(`summary`)を見て、要約して教える。「評価が4以上の席を教えて」は `min_rating: 4`。「内野指定席ってどうだった?」のように席種でも引ける。記録がなければ「記録はない」と答える
- 会場・スクリーン: 「A映画館のスクリーンは何がある?」(`list_venues`)、「スクリーン5は前方が首に来るとメモして」(`update_screen` の `note`)、「会場名を『A映画館 梅田』に直して」(`update_venue`)。席選びでは、スクリーンごとの平均評価と `note` も参考にして伝える
- 修正・削除: 「さっきの評価を★3に直して」(`update_seat_record`)、「その記録を消して」(`delete_seat_record`)
- 画面の日の詳細にも「座席の記録」があり、同じ記録を追加・編集・削除できる([guide.md](guide.md))

## レシートの明細(行ごとの記録)

1枚のレシートを、品名・金額の行ごとに記録できます。行ごとに別のカテゴリや税金のフラグを付けられるので、スーパーのレシートの中の日用品や、ドラッグストアのレシートの中の薬だけを分けて集計できます。

- 登録: レシートの写真を貼って「明細ごとに登録して」と頼む。AI が `add_transactions` の `items` に、品名と金額の行をそのまま入れる(値引きはマイナスの行)。**レシートの印字がマスター**で、金額・値引き・合計は印字どおりに登録する。品目の下にインデントや括弧で書かれた値引きは、前の品目の金額を書き換えず、別のマイナスの行にする(金額を調整して計算を合わせない)。明細の合計はレシートの合計(`amount`)と一致している必要があり、合わなければエラーと差額が返る。AI は品目の金額を変えずに読み直し、それでも合わなければ「端数・調整」の行で差額を合わせるか、利用者に確認する
- カテゴリ: 全部同じカテゴリなら取引のカテゴリだけを付ける。違う行(例: 洗剤=日用品)にだけ行のカテゴリを付ける。行のカテゴリ・フラグが空の行は、取引の値に従う
- カテゴリを省略すると、同じ店の直近の支出のカテゴリが自動で使われる(結果の `applied_default_category` に出る。違えば「カテゴリを直して」と頼む)
- 修正: 「さっきのレシートの明細を直して」→ `update_transaction` の `items` で明細を丸ごと置き換える(`[]` で明細を消す)。金額だけを変えるときも、明細の合計と合っている必要がある
- 見返し: `list_transactions` の各取引に `items` が付く。`summarize` は明細の行ごとに数える(`rows` の `count` は行の数。`count` はレシートの数、`lines` は行の数)
- 明細は任意。読み取れないレシートや1品だけの支出は、今までどおり合計だけで登録してよい

## レシートの情報(時刻・電話・住所・登録番号など)

後から店に問い合わせることがあるので(例: タクシーの領収書)、レシートに印字されている情報を取引ごとに残せます。すべて任意です。

| 項目 | 内容 |
| --- | --- |
| `paid_time` | 決済時刻(日本時間 `HH:MM`。日付は `date`) |
| `merchant_phone` | 店の電話番号 |
| `merchant_address` | 店の住所 |
| `invoice_number` | 適格請求書発行事業者の登録番号(`T` + 数字13桁。「登録番号」「事業者番号」の印字) |
| `clerk_name` | 対応した店員の名前(「担当」「責任者」「レジ」の印字) |
| `receipt_no` | レシート番号・伝票番号(例 P20261003152814) |
| `register_no` | レジ番号(例 0005) |
| `store_code` | 店番号・店舗コード(例 007832) |

- 登録: レシートの写真を貼って「登録して」と頼むと、AI が `add_transactions` に、**印字があるものだけ**入れる。印字が無い項目は省略する(推測で埋めない)。電話番号・住所・時刻は特に拾う
- 登録番号は、全角・小文字の t・ハイフンや空白入り(例: `T 0000-0000-00000`)でも受け付けて、`T0000000000000` の形にそろえる。`T` と数字13桁にならなければエラーになり、AI が読み取りを見直す
- **読み取れないレシート**: 薄くて判読できない項目は、AI は推測で埋めず、登録する前に3つの選択肢を示して確認する。(1) 利用者が値を教える、(2) 合計金額だけ登録する(明細は省略)、(3) 登録をやめる。決めるまで登録しない。電話番号だけ薄いなど、一部の項目だけ読めないときは、その項目だけ省いて登録し、結果を伝える。あとで「さっきの支出の電話番号は 03-0000-0000」と頼めば `update_transaction` で補える
- **メモには入れない**: 支払方法は口座(`account`)へ、レジ番号は `register_no`、伝票番号は `receipt_no`、店番号は `store_code`、電話・住所・登録番号・担当者はそれぞれの項目へ、税の内訳は `tax_lines`(明細の各行は `tax_rate`)へ入れる。メモ(`memo`)は、レシートのどの項目にも当てはまらない補足だけに使う。`add_transactions` / `update_transaction` の説明にこの方針が書いてある
- **支払方法が既存の口座にないとき**: メモに書かない。AI は先に `list_categories` で既存の口座を確認し(「クレジットカード」と「カード」など表記ゆれに注意)、本当に無ければ、あなたに確認してから `add_account` で追加し、その名前を `account` に入れる
- 修正・消去: `update_transaction` で直す。`null` を渡すと空にできる
- 検索: `list_transactions` の `keyword` で、店名・電話番号・住所・担当者名・メモ・レシート番号・登録番号から探す。例: 「担当が山田の支出を探して」「電話番号 03-0000-0000 の店の支出」。電話番号は、ハイフンや括弧の有無にかかわらず数字だけでも当たる
- 重複判定: 時刻がある取引は、時刻も含めて判定する。同じ日に同じ店で同額でも、時刻が違えば別の買い物として登録される
- 画面(`/tx/:id`)でも見られ、編集できる([guide.md](guide.md))

## 消費税の税率と税額(軽減税率の読み取り)

レシートに印字された税率と税額を、**印字どおりに**記録します。サーバーは税額を計算せず、税率の表も持ちません(8・10・0 のほか、将来の 1% や 0.5% もそのまま入ります)。下の「税金のフラグ」(医療費控除など)とは別物です。

| 項目 | 意味 |
| --- | --- |
| 明細の行の `tax_rate` | その行の税率(%。印字どおり。不明は省略) |
| 明細の行の `tax_label` | 印字どおりの記号(「※」「＊」「軽」「(軽)」「★」など。20文字まで。任意) |
| 取引の `tax_lines` | レシート下部の税率別の内訳。税率ごとに1行: `rate`、`taxable_amount`(対象金額)、`tax_amount`(消費税額)、`amount_basis`(`included`=税込・内税 / `excluded`=税抜・外税。分かるときだけ)、`label` |

- **軽減税率の読み取りの考え方**: 軽減税率の書き方は店ごとに違う(「※」「＊」「軽」「(軽)」「8%」「軽減」「★」など)。AI はレシートの凡例(「※は軽減税率対象商品」「★印は軽減税率(8%)適用」など)を読んで、行ごとの記号を数字の `tax_rate` にする。印字の記号は `tax_label` にそのまま残してよい
- **推測しない**: 凡例が無い・初めて見る書き方で記号の意味が分からない、内税か外税か分からない、印字が薄い、という場合は、AI は推測せずに利用者に聞く(分からない項目は省略して登録してもよい)。既存の「読み取れないレシートは推測しない」と同じ方針
- **内訳**: 「10%対象 ¥1,100 消費税 ¥100」「8%対象 ¥540 内消費税 ¥40」のような行を、`tax_lines` に印字どおりに入れる。印字が無い数字は省略し、AI も計算で補わない
- **合計が合わないとき**: エラーにはせず、応答の `tax_warnings` で知らせる(レシートがマスター)。AI は読み取りを見直すか、利用者に確認する
- **修正**: `update_transaction` の `tax_lines` は丸ごと置き換え(省略・`null` は変更なし、`[]` で消す)。明細の `tax_rate` / `tax_label` は `items` といっしょに送る
- **集計**: `summarize_tax`。集計するのは `tax_lines` の数字だけ(明細の `tax_rate` から税額は計算しない)。結果の `coverage.without_tax_lines` が「税の内訳が無く、集計に含まれていない支出」の件数と金額なので、AI は合計といっしょに必ず伝える。例: 「今年の消費税を税率別に合計して」「2026年の月別の消費税は?」
- 画面: 明細ページの「編集」で入力でき、`/tax` で税率別の表が見られる([guide.md](guide.md))

## 確定申告用の「税金のフラグ」

支出に、控除用のフラグを1つ付けられます。**金額の記録と年ごとの合計を出すだけ**で、控除の対象になるか・控除額・上限の判定はしません(判定は自分で行います)。

| `tax_flag` | 意味 |
| --- | --- |
| `medical` | 医療費控除 |
| `self_medication` | セルフメディケーション税制 |
| `donation` | 寄附金控除(ふるさと納税など) |

- 登録・修正: `add_transactions` / `update_transaction` の `tax_flag`。「この薬局のレシートは医療費控除に」「さっきの取引のフラグを外して」(`null` で解除)のように頼む。薬局のレシートは `medical` か `self_medication` のどちらにするかを、AI が聞いてくることがある
- 明細: `list_transactions` の `tax_flag`(値を指定、または `any` で何かのフラグが付いたもの全部)。年の範囲(`from` / `to`)と組み合わせる。レシートの明細の行ごとにもフラグを付けられ(例: ドラッグストアのレシートの薬の行だけ `self_medication`)、行のどれかが当てはまる取引が出る
- 年ごとの合計: `summarize` の `group_by: "tax_flag"` に、年の範囲を付ける。例: 「2026年のセルフメディケーションの合計を出して」。行名は日本語のラベル、フラグなしは「(フラグなし)」
- 画面(日の詳細)でも、支出の追加・編集の「税金のフラグ」で付け外しできる

## 写真を登録・見返す

写真の実体は、チャットからは送れません。登録は「リンクを開いて選ぶ」流れです。

1. チャットで「今日のレシート写真を残したい」「この取引に写真を付けたい」と頼む。
2. AI が `create_photo_upload_link` でリンクを返す(`<オリジン>/photos/add?date=...` など。日付・取引・出来事のどれに紐づけるかが入っている)。
3. リンクを開く。Cloudflare Access のログインを通った、あなた自身のブラウザでだけ開ける(リンクに期限やトークンは付かない)。
4. 画面で写真を選んで追加する。

見返すときは、AI が `list_photos` で写真の id を調べ、`get_photos` で画像を読みます。レシート写真を AI に読み取らせて `add_transactions` で登録する、という使い方もできます。

リンクの先は写真の追加画面(`/photos/add`)です。日付(と、あれば取引・出来事)に紐づけて、複数の写真をまとめて追加できます。リンクが正しくないときは、その旨が表示されます(AI にもう一度リンクを作ってもらう)。

## ツールの「常に許可」

チャットでツールを初めて使うとき、実行の許可を求められます。次の3つは、読み取りか無害な操作なので「常に許可」でかまいません。

- `create_photo_upload_link`: リンクを作るだけで、何も保存しない
- `list_photos`: 読み取りだけ
- `get_photos`: 読み取りだけ

`list_transactions` / `list_events` / `list_categories` / `summarize` も読み取りだけです。データを変える・消すもの(`add_transactions`、`update_transaction`、`delete_transaction`(`delete_photos` を付けると写真も消える)、`add_event`、`update_event`、`add_category`、`update_category`、`delete_category`、`rename_group`、`add_account`、`update_account`、`delete_account`)は、内容を見て許可するのがおすすめです。特に `delete_transaction`、`delete_category`、`delete_account` は取り消せません。削除系は、毎回確認が出てかまいません(「常に許可」にしない)。

## カテゴリを増やす

Zaim のように、大分類の下にサブカテゴリを作れます。例: 「大分類『住まい』の下に『光熱費』のカテゴリを作って」 → `add_category` で作ったあと、「電気代 8,000円を登録して」で `add_transactions` の `category` に使われます。

- 名前(サブカテゴリ)は全体で一意(30文字まで)。大分類は20文字まで。既存の大分類でも、新しい名前でもよい
- アイコン: `add_category` / `update_category` の `icon` に、アイコンのキーを渡す(`update_category` は `null` で外す)。AI は名前に合うものを選ぶ(「タクシー」→ `taxi`)。`list_categories` の戻りの各カテゴリにも `icon` が入る(未設定は `null`)。選べるキー(キー=意味): `food`=食事、`cafe`=カフェ、`grocery`=食料品、`daily`=日用品、`transit`=電車・バス、`taxi`=タクシー、`car`=クルマ、`fuel`=ガソリン、`social`=交際、`entertainment`=娯楽・音楽、`movie`=映画、`education`=教育・教養、`book`=本、`clothes`=服、`beauty`=美容、`medical`=医療、`insurance`=保険、`phone`=通信、`utility`=水道・光熱、`home`=住まい、`tax`=税金、`bigspend`=大型出費、`travel`=旅行、`gift`=贈り物、`kids`=子ども、`pet`=ペット、`sports`=スポーツ、`hobby`=趣味、`subscription`=サブスク、`bank`=金融、`other`=その他。一覧にない値はエラー(選べるキーが返る)
- 整理: `update_category`(名前の変更・大分類の移動)、`rename_group`(大分類の名前の変更。既存の大分類と同名にすると統合)、`delete_category`(使っている支出があるときは `move_to` に移し先を指定する。AI は先に `list_categories` の `usage` を見る)
- 画面の `/categories`(ナビの「カテゴリ」)でも同じことができます

## 口座(支払方法)を増やす

「Suica のほかに『PayPay』の支払方法を作って」 → `add_account` で作ったあと、「500円のコーヒーを PayPay で登録して」で `add_transactions` の `account` に使われます。未知の口座名は自動では増えず、エラー(選べる値つき)になります。

- AI は、利用者に確認してから追加します。先に `list_categories` の `accounts` で既存を見て、「現金」と「げんきん」のような表記ゆれで増やしません
- 名前は全体で一意(30文字まで)。`update_account` で名前を変えると、その口座を使っている支出の表示も自動で新しい名前になります
- `delete_account`: 使っている支出があるときは `move_to` に移し先の口座を指定します(支出そのものは消えません)
- 画面の `/categories` の「支払方法」でも同じことができます

## うまくいかないとき

| 症状 | 見る場所 |
| --- | --- |
| 接続時に、リダイレクトURIの不一致のようなエラー | Access アプリの「許可するリダイレクトURI」に、エラーに出たURLを追加する |
| ログインはできたが、ツールが失敗する | Worker の Observability(ログ)。`auth: ...` の行に、弾いた理由が出る |
| 「ACCESS_... が未設定」 | シークレットを入れた場所が違う。**ランタイム**変数とシークレットに入れる([setup.md](setup.md) の手順4) |
| `claim=aud` | `ACCESS_AUD` が、Access アプリの AUD タグと違う |
| 写真が `get_photos` で見えない | `list_photos` で id を確かめる。合計が約6MBを超えると、超えた分は返らない(返らなかった id で呼び直す) |
| 登録で「テーブルがない」旨のエラー | D1 のマイグレーションが未適用。デプロイコマンドに `d1 migrations apply` が入っているか確認する |
