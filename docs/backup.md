# バックアップ(JSONLのエクスポートとインポート)

実値(ドメインなど)は書きません。`<サブドメイン>.<ドメイン>` は、自分の公開先に読み替えてください。

## エクスポート(全データを書き出す)

ブラウザで、ログインしたまま `https://<サブドメイン>.<ドメイン>/backup` を開きます(ナビの「エクスポート」。スマホはホームの右上から)。

1. 「バックアップ(JSONL)」の **バックアップをダウンロード** を押すと、全期間の記録が `receipt2life-YYYYMMDD.jsonl` として保存されます
2. 保存したファイルは実データなので、公開の場所に置かない

補足: `https://<サブドメイン>.<ドメイン>/export` を直接開いても、同じファイルが保存されます(画面のボタンはこのURLを呼んでいます)。期間指定や件数の表示は、`/export` が対応していないので画面にもありません。

ファイルの中身:

- 1行1レコードで、`type` が `event` → `transaction` → `item` → `attachment` → `link` → `screen` → `seat_record` → `subscription` の順に並ぶ(`item` はレシートの明細の行。`id`, `transaction_id`, `position`, `name`, `amount`, `category`, `tax_flag`, `memo`, `tax_rate`(消費税の税率%。不明は `null`), `tax_label`(印字の記号), `product` / `quantity` / `content_amount` / `content_unit` / `jan_code`(商品の情報。なしは `null`。単価は保存せず、計算する), `created_at`。`category` と `tax_flag` は行自身の値で、`null` は取引の値に従う。`link` は出来事・取引・日付に付けたXの投稿・YouTubeの動画・Instagramの投稿・ウェブのページのURL。`id`, `url`, `kind`, `title`, `description`, `date`, `transaction_id`, `event_id`, `created_at`。`screen` は会場のスクリーン。`id`, `venue`(会場名), `name`(スクリーン名), `note`(そのスクリーンの特徴), `created_at`(`note` を失わないための行。座席の記録より前に読み込まれる)。`seat_record` は映画館などの座席の記録。`id`, `date`, `title`, `venue`(会場名), `screen`(スクリーン・エリア名), `seat`, `seat_class`(席種), `rating`, `note`, `transaction_id`, `created_at`(会場・スクリーンは名前で持つので、会場とスクリーンが別のレコードになる前の古いバックアップもそのまま読める)。取引に紐づけたものは、読み込み時に先に取引が入る)
- `subscription` はサブスク・保険などの固定費(別枠)。`id`, `name`, `kind`, `amount`, `period`, `currency`(`JPY` / `USD` など。円は `JPY`), `foreign_amount`, `exchange_rate`, `previous_foreign_amount`(外貨のときだけ), `billing_month`, `billing_day`, `previous_amount`, `amount_changed_on`, `price_checked_on`, `url`, `note`, `active`(`true` / `false`), `created_at`, `updated_at`(なしは `null`)
- カテゴリと口座は、名前で書き出される
- `transaction` の行には、レシートの情報 `paid_time` / `merchant_phone` / `merchant_address` / `invoice_number` / `clerk_name` / `receipt_no` / `register_no` / `store_code`(なしは `null`)も入る。`register_no` / `store_code` の無い古いバックアップもそのまま戻せる(戻すと `null`)
- `transaction` の行には `tax_flag`(税金の控除用フラグ。`medical` / `self_medication` / `donation`、なしは `null`)が入る
- `transaction` の行には `tax_lines`(レシート下部の税率別の内訳。`rate`, `taxable_amount`, `tax_amount`, `amount_basis`, `label` の配列。税率の高い順。なしは `[]`)が入れ子で入る。内訳の `id` は書き出さない(戻すと新しい id になる)。明細と違って別の行にしないのは、税率ごとの小さな表で、取引といっしょに読み書きするため
- 写真の実体は含まれない(zip でまとめて書き出す機能は未実装。今後の候補)

保存したファイルは、**実データ**です。リポジトリには置かないでください(`exports/` と `backup/` は `.gitignore` 済み)。

## 読み物として書き出す(Markdown・HTML)

`/backup` の「日記として読む」で、月・年・日付の範囲(366日まで)を選び、**Markdown** か **HTML** を押します。URLを直接開いても同じです(ログインしたまま)。

| URL | 内容 |
| --- | --- |
| `/export/markdown?month=2026-10` | Markdown(`.md`) |
| `/export/html?month=2026-10` | CSSつきの1つのHTML(`.html`。スクリプトなし) |

期間は `month=YYYY-MM`、`year=YYYY`、`from=YYYY-MM-DD&to=YYYY-MM-DD` のどれか1つ(何も付けないと今月)。正しくない指定は400です。

中身: サマリ(合計・件数・支出のあった日・1日平均)、カテゴリ別(表。Markdownは Mermaid の円グラフ、HTMLは棒)、月ごとのカレンダー(日ごとの金額と期間メモの色🟥🟧🟩🟦🟪)、期間メモ、日別の記録(取引と明細・税の内訳・座席の記録・写真の枚数とキャプション・リンク)。

- **読み物であって、バックアップではありません。** 戻す(インポート)ことはできません。戻せるのはJSONLだけです
- 写真の画像は含まれません(枚数とキャプションだけ)
- 保存したファイルは実データです。公開の場所に置かない

## インポート(書き出したものを戻す・移行する)

### 画面から(`/backup`)

1. 「バックアップを読み込む」の **ファイルを選ぶ** で、書き出した JSONL を選ぶ(ファイル名、大きさ、行数が出る)
   - 読み込む前にブラウザで上限(**50MB・10万行**。空行を除く行数か、JSON 配列の件数)を調べる。超える・空・読めないときは、その場でエラーが出て送られない。中身の判定はサーバーが行う
   - **大きなファイルは、自動で小分けして、順に送る**(1回に400行・1MBまで。サーバーの1回の上限5MB・5000行より、ずっと小さい)。取引と、その明細(`item` の行)は、必ず同じ回に入れる。画面には「N回に分けて送る」と出て、読み込み中は進み具合(3 / 12)が出る
2. **読み込む** を押す
3. 「読み込み結果」に件数が出る
   - 登録: 新しく入った行
   - 重複でスキップ: 同日・同額・同じ店などで、登録しなかった行
   - 既にある: 同じ `id` が既にあり、登録しなかった行(同じファイルを何度戻しても増えない)
   - 読めなかった行: エラーになった行。理由は最大 50 件まで下に出て、超える分は「ほかN件」になる。行番号は、元のファイルの行(小分けする前の行)
   - **途中で止まったとき**(通信の失敗など): 「N回に分けて送るうち、M回目で止まりました」と出る。もう一度「読み込む」を押すと、続きから戻せる(すでに入った分は「既にある」としてスキップされ、増えない)。回数の制限(429)に当たったときは、画面が待って送り直す
   - 大きなバックアップを戻すと、D1 の「書いた行」の1日の上限(無料プランは10万行)を使う。取引1件(明細つき)で、行数が数行〜十数行分増える(索引も数える)。上限に近づいたら、メニューの「使用量」で確かめる。上限に達しても、翌日(日本時間の午前9時)に、同じファイルをもう一度読み込めば、続きから戻せる

### API として

`POST /import` に、JSONL か JSON 配列を送ります。行ごとの結果(成功、重複スキップ、id 既存スキップ、エラー理由)が返ります。画面も同じ API を呼んでいます。

- 上限は 5MB または 5000 行(件)(**1回のリクエストの上限**。画面は、これより大きなファイルを、自動で小分けして何回かに送る)。超えると 413、空は 400
- エクスポートした行(`id` と `created_at` がある取引)は、重複判定を飛ばして、そのまま戻る
- `id` か `created_at` が無い行は、重複判定をする(同日・同額・同じ店はスキップ)
- `tax_flag` が無い古いバックアップも、そのまま取り込める(フラグなしになる)。`tax_flag` に未知の値がある行は、その行だけエラー
- レシートの情報(`paid_time` など6項目)が無い古いバックアップも、そのまま取り込める(項目は空になる)。値があれば登録時と同じ規則で検証・正規化し(例: `invoice_number` は `T` + 数字13桁に正規化、合わなければその行だけエラー)、重複判定は `paid_time` があれば時刻も含める
- 明細(`item` の行)は、同じファイルの取引の行(`id` が `transaction_id` と一致)といっしょに取り込む。取引と明細は一度に書くので、片方だけが残ることはない
  - 明細の合計が取引の `amount` と合わないときは、その取引と明細の行がエラー(差額が出る)。明細のカテゴリが未知(エクスポートした行では自動で作る)、1取引50行を超える、明細の `id` が既にある場合も同じ
  - 取引が `skipped_exists`(同じ id がある)・`skipped_duplicate` なら、明細の行も同じ結果になる。バックアップを同じDBに何度戻しても増えない
  - 取引の行がファイルに無い明細の行は、同じ `id` の明細が既にあれば `skipped_exists`、無ければエラー
  - 取引の行の中に `items` を入れ子で書いた行はエラー(明細は `item` の行で書く)
  - 明細の無い古いバックアップも、そのまま取り込める
  - 明細の行の `tax_rate` / `tax_label` や、商品の情報(`product` / `quantity` / `content_amount` / `content_unit`)が無い古いバックアップも、そのまま取り込める(不明・なしになる)。`content_amount` と `content_unit` は、片方だけの行はその行だけエラー。`jan_code` は、8桁か13桁で検査桁が合わない行もその行だけエラー。範囲外の税率(0〜100の外、小数第4位以下)や21文字以上の記号は、その取引と明細の行がエラー
- 取引の行の `tax_lines`(税の内訳)は、取引といっしょに書く。無い古いバックアップは内訳なしで取り込める。同じ税率が2つある・範囲外の税率・負や小数の金額は、その取引(と明細の行)がエラー。合計が取引の金額と合わなくてもエラーにはしない(レシートがマスター)
- 未知の口座の名前は、その行だけエラーになる(自動では作らない)
- 未知のカテゴリの名前も、その行だけエラーになる。ただし**エクスポートした行(`id` と `created_at` がある取引)**は復元とみなし、取り込み先に無いカテゴリを自動で作る。バックアップの行には大分類が入っていないので、大分類は「その他」になる(必要なら、あとで `/categories` の画面か MCP の `update_category` で移す)。名前が30文字を超える・前後に空白があるものは作らず、その行がエラーになる。実際に取り込む行が使うカテゴリだけを作る(スキップされる行のぶんは作らない)
- `link` の行は、URLを登録時と同じ規則で検証・正規化する(`http:`、内部向けのホスト、`user:pass@` 付き、`kind` がURLと合わないものは、その行だけエラー)。紐づけ先の取引・出来事が無い行もエラー
- `link` の重複: 同じ `id` は `skipped_exists`。`id` が違っても、同じ紐づけ先に同じ正規化URLがあれば `skipped_duplicate`(バックアップを同じDBに何度戻しても増えない)
- `subscription` の行は、登録と同じ規則で検証する(`name` `period` と金額が必須。円は `amount`、外貨は `currency` と `foreign_amount` と `exchange_rate`(円の `amount` があればそのまま使い、無ければ計算する)。`period` は `monthly` / `yearly`、月払いに `billing_month` は付けられない、`url` は https のみ。範囲外や未知の項目は、その行だけエラー)。同じ `id` は `skipped_exists`(何度戻しても増えない)
- `seat_record` の行は、座席の記録と同じ規則で検証する(`date` `venue` `seat` が必須、`rating` は1〜5の整数、`title`(作品名・公演名。任意。空は未指定)・`venue` 100文字・`screen` 100文字・`seat` 50文字・`seat_class`(席種。任意。空は未指定)50文字・`note` 200文字まで。範囲外や未知の項目は、その行だけエラー)。`transaction_id` がある行は、その取引が取り込み先に無ければその行だけエラー(取引はファイルの順に関係なく先に入る)。同じ `id` は `skipped_exists`(何度戻しても増えない)。`title` や `seat_class` の無い旧形式の行もそのまま取り込める(未設定になる)
- 会場・スクリーンは、`seat_record` の `venue` / `screen` の名前から、無ければ作って(名前の完全一致で1件にまとまる)取り込み先の記録につなぐ。`screen` の行は `venue`・`name` が必須(`note` は200文字まで)。同じ `id`、または同じ(会場, スクリーン名)が既にあれば `skipped_exists`(既存の `note` は変えない)。記録もスクリーンも無い会場は書き出されない

ブラウザ以外(`curl` など)から POST するには、サービストークンが必要です。ステージング環境(別の Worker・D1・R2・サービストークン)がまだ作られていないため、その手順は未記入です。ステージングを作ったあとに、ここへ書きます。

## 写真のバックアップ(ZIP)

JSONL には写真の「情報」(日付・メモ・どの取引か)は入るが、画像そのものは入らない。画像は `/backup` の「写真」カードで、ZIP にして保存する。

- 「写真をダウンロード(ZIP)」: 全部の写真を、ブラウザで集めて ZIP にする(圧縮なし)。100MB または 500枚ごとに、別のファイル(`…-part1.zip`、`part2`…)に分かれる。Chrome が「複数のファイルのダウンロードを許可しますか」と聞いたら、許可する
- 戻すとき: **先に JSONL を読み込み、次に ZIP を選んで「写真を戻す」**。写真の情報が先に必要なため。ZIP は複数まとめて選べる。すでにある画像は上書きしない(何度やっても安全)
- パソコンでの作業を想定している

## 戻す用の API

`PUT /api/photos/:id/restore`(本文は画像のバイト列、5MB まで)。詳しくは docs/api.md。

## バックアップの履歴とお知らせ

- JSONL を書き出す(`GET /export`)たびに、日時を1行記録する(最新の50件だけ残す)。写真の ZIP を作るための読み出し(`?for=photos`)は数えない
- `/backup` に「最後のバックアップ: 日付(N日前)」を出す
- 最後から30日以上たったとき(まだ取っていないときも。記録が1件もない空の状態は除く)、ホームに「バックアップを書き出しましょう」のお知らせを出す
- 状況は `GET /api/backup-status`(`last_backup_at`・`days_since`・`has_data`・`remind`)
