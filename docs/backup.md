# バックアップ(JSONLのエクスポートとインポート)

実値(ドメインなど)は書きません。`<サブドメイン>.<ドメイン>` は、自分の公開先に読み替えてください。

## エクスポート(全データを書き出す)

ブラウザで、ログインしたまま `https://<サブドメイン>.<ドメイン>/backup` を開きます(ナビの「エクスポート」。スマホはホームの右上から)。

1. 「バックアップ(JSONL)」の **バックアップをダウンロード** を押すと、全期間の記録が `receipt2life-YYYYMMDD.jsonl` として保存されます
2. 保存したファイルは実データなので、公開の場所に置かない

補足: `https://<サブドメイン>.<ドメイン>/export` を直接開いても、同じファイルが保存されます(画面のボタンはこのURLを呼んでいます)。期間指定や件数の表示は、`/export` が対応していないので画面にもありません。

ファイルの中身:

- 1行1レコードで、`type` が `event` → `transaction` → `item` → `attachment` → `link` → `seat_record` の順に並ぶ(`item` はレシートの明細の行。`id`, `transaction_id`, `position`, `name`, `amount`, `category`, `tax_flag`, `memo`, `created_at`。`category` と `tax_flag` は行自身の値で、`null` は取引の値に従う。`link` は出来事・取引・日付に付けたXの投稿・YouTubeの動画のURL。`id`, `url`, `kind`, `title`, `date`, `transaction_id`, `event_id`, `created_at`。`seat_record` は映画館などの座席の記録。`id`, `date`, `venue`, `screen`, `seat`, `rating`, `note`, `transaction_id`, `created_at`。取引に紐づけたものは、読み込み時に先に取引が入る)
- カテゴリと口座は、名前で書き出される
- `transaction` の行には、レシートの情報 `paid_time` / `merchant_phone` / `merchant_address` / `invoice_number` / `clerk_name` / `receipt_no`(なしは `null`)も入る
- `transaction` の行には `tax_flag`(税金の控除用フラグ。`medical` / `self_medication` / `donation`、なしは `null`)が入る
- 写真の実体は含まれない(zip でまとめて書き出す機能は未実装。今後の候補)

保存したファイルは、**実データ**です。リポジトリには置かないでください(`exports/` と `backup/` は `.gitignore` 済み)。

## インポート(書き出したものを戻す・移行する)

### 画面から(`/backup`)

1. 「バックアップを読み込む」の **ファイルを選ぶ** で、書き出した JSONL を選ぶ(ファイル名、大きさ、行数が出る)
   - 読み込む前にブラウザで上限(5MB・5000 行。空行を除く行数か、JSON 配列の件数)を調べる。超える・空・読めないときは、その場でエラーが出て送られない。中身の判定はサーバーが行う
2. **読み込む** を押す
3. 「読み込み結果」に件数が出る
   - 登録: 新しく入った行
   - 重複でスキップ: 同日・同額・同じ店などで、登録しなかった行
   - 既にある: 同じ `id` が既にあり、登録しなかった行(同じファイルを何度戻しても増えない)
   - 読めなかった行: エラーになった行。理由は最大 50 件まで下に出て、超える分は「ほかN件」になる

### API として

`POST /import` に、JSONL か JSON 配列を送ります。行ごとの結果(成功、重複スキップ、id 既存スキップ、エラー理由)が返ります。画面も同じ API を呼んでいます。

- 上限は 5MB または 5000 行(件)。超えると 413、空は 400
- エクスポートした行(`id` と `created_at` がある取引)は、重複判定を飛ばして、そのまま戻る
- `id` か `created_at` が無い行は、重複判定をする(同日・同額・同じ店はスキップ)
- `tax_flag` が無い古いバックアップも、そのまま取り込める(フラグなしになる)。`tax_flag` に未知の値がある行は、その行だけエラー
- レシートの情報(`paid_time` など6項目)が無い古いバックアップも、そのまま取り込める(項目は空になる)。値があれば登録時と同じ規則で検証・正規化し(例: `invoice_number` は `T` + 数字13桁に正規化、合わなければその行だけエラー)、重複判定は `paid_time` があれば時刻も含める
- 明細(`item` の行)は、同じファイルの取引の行(`id` が `transaction_id` と一致)といっしょに取り込む。取引と明細は一度に書くので、片方だけが残ることはない
  - 明細の合計が取引の `amount` と合わないときは、その取引と明細の行がエラー(差額が出る)。明細のカテゴリが未知(エクスポートした行では自動で作る)、1取引50行を超える、明細の `id` が既にある場合も同じ
  - 取引が `skipped_exists`(同じ id がある)・`skipped_duplicate` なら、明細の行も同じ結果になる。バックアップを同じDBに何度戻しても増えない
  - 取引の行がファイルに無い明細の行は、同じ `id` の明細が既にあれば `skipped_exists`、無ければエラー
  - 取引の行の中に `items` を入れ子で書いた行はエラー(明細は `item` の行で書く)
  - 明細の無い古いバックアップも、そのまま取り込める
- 未知の口座の名前は、その行だけエラーになる(自動では作らない)
- 未知のカテゴリの名前も、その行だけエラーになる。ただし**エクスポートした行(`id` と `created_at` がある取引)**は復元とみなし、取り込み先に無いカテゴリを自動で作る。バックアップの行には大分類が入っていないので、大分類は「その他」になる(必要なら、あとで `/categories` の画面か MCP の `update_category` で移す)。名前が30文字を超える・前後に空白があるものは作らず、その行がエラーになる。実際に取り込む行が使うカテゴリだけを作る(スキップされる行のぶんは作らない)
- `link` の行は、URLを登録時と同じ規則で検証・正規化する(許可リスト外のURL、`http:`、`user:pass@` 付き、`kind` がURLと合わないものは、その行だけエラー)。紐づけ先の取引・出来事が無い行もエラー
- `link` の重複: 同じ `id` は `skipped_exists`。`id` が違っても、同じ紐づけ先に同じ正規化URLがあれば `skipped_duplicate`(バックアップを同じDBに何度戻しても増えない)
- `seat_record` の行は、座席の記録と同じ規則で検証する(`date` `venue` `seat` が必須、`rating` は1〜5の整数、`venue` 100文字・`screen` 100文字・`seat` 50文字・`note` 200文字まで。範囲外や未知の項目は、その行だけエラー)。`transaction_id` がある行は、その取引が取り込み先に無ければその行だけエラー(取引はファイルの順に関係なく先に入る)。同じ `id` は `skipped_exists`(何度戻しても増えない)

ブラウザ以外(`curl` など)から POST するには、サービストークンが必要です。ステージング環境(別の Worker・D1・R2・サービストークン)がまだ作られていないため、その手順は未記入です。ステージングを作ったあとに、ここへ書きます。
